### 3. Hotfix: serverExternalPackages for isomorphic-dompurify
**Commit:** `f77e7e9` (bundled with entry 4)

**Feature:**
- Added `serverExternalPackages: ['isomorphic-dompurify']` to `next.config.ts`. Resolves a Bun + Turbopack interaction bug where the nested `jsdom@28` (required by `isomorphic-dompurify@^2.36`) was installed under a hashed name (`jsdom-<hash>`) and Turbopack baked that hashed name into chunked output, then failed to resolve at runtime. Marking the package as external lets Node's `require` follow Bun's nested-dep resolution naturally.
- Cleared the stale `.next` Turbopack cache as part of the verification.
- Verified by re-running `bun run dev` and curling `/notes/new` (which imports `isomorphic-dompurify`) — compiled cleanly with no `Cannot find package 'jsdom-<hash>'` error.

**Out of OpenSpec scope** by user direction (treated as a one-line `next.config.ts` hotfix rather than spinning up a propose flow).

### 4. Add Remove account flow
**Commit:** `f77e7e9`

**Feature:**
- Added a self-service Remove account flow. New `/settings` page with a Danger zone that opens a type-email confirmation modal; on confirm, the `removeAccount` server action runs a single SQLite transaction deleting the user's `notes`, `session`, `account`, and `user` rows in dependency order, then signs out via better-auth and redirects to `/`.
- Added `removeAccountSchema` (zod) to `lib/validation.ts` for defense-in-depth at the action boundary.
- Added a plain `<Link href='/settings'>Settings</Link>` to `components/header.tsx`, gated on the same `user` prop the Logout button uses (visible only when signed in).
- Introduced a new `account-management` capability spec with four ADDED requirements: header-link visibility, settings auth-gate, transactional account-removal contract (with three scenarios), and the trust-the-session security rule (with a tampered-form scenario).
- Brainstorming spec: `docs/superpowers/specs/2026-04-29-remove-account-design.md`.

**Code Review Findings, if any:**
| Severity | Issue | Fix |
|---|---|---|
| HIGH (group 2) | `signOut` was called *after* the session row was deleted — better-auth could not look up its own session and may have left a stale browser cookie. | Reordered: `signOut` runs *before* the cascade transaction. Aborts with an error if `signOut` itself throws. |
| HIGH (group 2) | Test suite missed the "DB failure during deletion" control-flow scenario the spec promised. | Added two cases: (a) signOut throws → no DELETEs run; (b) cascade transaction throws → error returned, no redirect. |
| MEDIUM (group 2) | `await headers()` was called twice per action invocation. | Hoisted to a single `reqHeaders` const reused for `getSession` and `signOut`. |
| MEDIUM (group 2) | `RemoveAccountState['success']` field was dead (action only returns `{ error }` or throws). | Dropped `success` from the interface; form's initial state is `{}`. |
| LOW (group 1) | Test assertions for the schema only check `.toBeDefined()`, weaker than peers using `.toContain('...')`. | Acknowledged, not changed (taste-level; reviewer flagged as non-blocking). |
| LOW (group 3) | Confirm button used `disabled:bg-red-300` while the rest of the codebase uses `disabled:opacity-50`. | Aligned to `disabled:opacity-50 disabled:cursor-not-allowed`. |
| LOW (group 3) | Modal lacks ESC-to-close and focus trap. | Acknowledged as a deliberate trade-off (manual-smoke covers it; native `<dialog>` upgrade flagged for future). |

**Discovered constraint (logged on tasks.md 2.1):**
- Vitest spawns its workers under Node, so `import { db } from '@/lib/db'` (which imports `bun:sqlite`) fails at test time with "Cannot bundle Node.js built-in 'bun:sqlite'". The action test file mocks `@/lib/db` instead and asserts on mock interactions. Real cascade rollback / FK semantics are now verified by manual smoke (task 4.3) rather than automated. A follow-up could add an integration test running under `bun test` (the native runner) to exercise the real DB.
