# Dev Log — 2026-05-03

### 1. Workflow rule: UI-bearing changes must include an E2E test task

**Commit:** `1d3fa1a`

**Feature:**

- Added a new `tasks` rule to `openspec/config.yaml` so `/opsx:propose` scaffolds an E2E test task **immediately before** `superpowers:verification-before-completion` whenever a change touches `app/`, `components/`, or any client-rendered behavior. Pure backend/lib/schema/test-only changes are exempt.
- The rule allows two acceptable patterns: a manual `bun run dev` walkthrough with explicit URL/actions/expected outcomes, OR an automated flow driven by the Playwright MCP tools (`mcp__plugin_playwright_playwright__*`).
- Mirrored the rule into `CLAUDE.md`'s "Spec-driven workflow" section so the project guidance and the proposer instructions stay in sync (later revised to E2E terminology in a follow-up edit).

**Tests:** No code change; rule applies to future `/opsx:propose` runs.

### 2. Workflow rule: `/opsx:propose` ALWAYS runs `superpowers:brainstorming`

**Commit:** _bundled with #3_

**Feature:**

- Reversed the prior "skip brainstorming for non-UI changes" policy. Brainstorming now runs for every `/opsx:propose` invocation regardless of UI surface.
- Updated `openspec/config.yaml` proposal rule to *"Every proposal must reference the brainstorming spec produced under `docs/superpowers/specs/`. /opsx:propose ALWAYS runs superpowers:brainstorming first regardless of whether the change has UI surface."*
- Replaced auto-memory: deleted `feedback_brainstorming_skip.md`, added `feedback_brainstorming_always.md` with the new rule + reasoning.

**Why:** Brainstorming surfaces hidden assumptions even on changes that look simple ("just add a helper", "just add a column"); the cost of one short dialogue is cheaper than discovering the wrong scope mid-implementation.

**Commit:** _pending_
