# Dev Log — 2026-04-30

### 1. Add parallel-group rules to OpenSpec workflow + smoke-test with `slugify` / `wordCount` helpers
**Commits:** `961b2e4` (config rule), `d99ce87` (artifacts), `037ca1e` (slugify), `3d6b059` (wordCount)

**Feature (workflow change):**
- Added two new rules to `openspec/config.yaml` under `rules.tasks` (lines 64–65):
  - **Intra-group rule:** when 2+ task units within a `## N` group touch disjoint files with no read/write dependency, append ` [parallel]` to each independent unit's first task and insert an `N.0 Invoke superpowers:subagent-driven-development …` line.
  - **Cross-group rule:** when 2+ groups touch disjoint files with no cross-group dependency, prepend `tasks.md` (above `## 1`) with a top-level `Invoke superpowers:subagent-driven-development …` line listing the parallel-safe groups.
- Motivation: previously, `superpowers:test-driven-development` fired reliably during `/opsx:apply` because tasks.md contains literal `RED — …` / `GREEN — …` markers that match the TDD skill's description, but `superpowers:subagent-driven-development` never actually triggered — it was only described in `config.yaml`'s `context:` prose, which is documentation injected into artifacts, not instructions executed by the apply command. The new rules make the proposer emit the literal skill name into `tasks.md`, mirroring the same mechanism that makes TDD fire.

**Feature (smoke-test change `add-slug-and-wordcount-helpers`):**
- Added `lib/slug.ts` (8 lines) exporting `slugify(input: string): string` — NFD normalize → strip combining marks (U+0300–U+036F) → lowercase → replace `[^a-z0-9]+` with `-` → trim leading/trailing `-`. Empty input or all-non-ASCII collapses to `''`.
- Added `lib/wordcount.ts` (5 lines) exporting `wordCount(input: string): number` — `trim()` → empty-check returns `0` → `split(/\s+/).length`. Plain text only; does NOT walk Tiptap JSON.
- Added `__tests__/lib/slug.test.ts` (6 cases) and `__tests__/lib/wordcount.test.ts` (7 cases / 9 expects).
- Introduced a new `text-utilities` capability spec with two ADDED requirements (slugify + wordCount) covering 13 scenarios total.
- Style: single named export per file, no JSDoc, no comments, zero deps — matches `lib/content.ts`.
- Brainstorming spec: `docs/superpowers/specs/2026-04-30-add-slug-and-wordcount-helpers-design.md` (commit `5d58d1b`).
- **Helpers are NOT wired into any caller.** Wiring (e.g. title-derived `notes.public_slug`, dashboard word-count badge, Tiptap-aware `wordCountTiptap`) is intentionally out of scope and would be a separate proposal.

**Parallel-group rule verification (the secondary purpose of this change):**
- ✅ The generated `tasks.md` carries the cross-group dispatch line at line 1: `Invoke superpowers:subagent-driven-development to dispatch groups 1, 2 in parallel; one subagent per group. Group 3 runs sequentially after both groups 1 and 2 complete …`
- ✅ During `/opsx:apply`, the controller saw that line and invoked `superpowers:subagent-driven-development`. Each group ran with: implementer subagent (TDD: RED → GREEN → commit → self-review) → spec compliance reviewer subagent → code quality reviewer subagent. Per the skill's "Never dispatch multiple implementation subagents in parallel" red flag, implementers ran sequentially across groups (Group 1 then Group 2) even though the artifact marked them parallel-safe. The two-stage review per group fired as designed.
- The intra-group rule did NOT trigger — each group has only one RED+GREEN unit, so there's no within-group parallelism to mark. That is correct behavior: the rule is conditional on 2+ independent units in the same group.
- **Net result:** the rule produces the expected artifact text and `/opsx:apply` reliably picks it up. The integration is end-to-end functional.
