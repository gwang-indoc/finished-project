# Dev Log — 2026-05-01

### 1. Add `truncate` and `readingTime` helpers (text-utilities) + `subagent-driven-development` smoke test

**Commit:** `d4ba6f0`

**Feature:**

- Added `lib/truncate.ts` exporting `truncate(input: string, maxLength: number): string` — returns input unchanged when `input.length <= maxLength`; otherwise `input.slice(0, maxLength - 1) + '…'` so the result's `.length` is exactly `maxLength`. Operates on UTF-16 code units; behavior is undefined for `maxLength < 1`.
- Added `lib/reading-time.ts` exporting `readingTime(input: string): number` — `Math.ceil(wordCount(input) / 200)` for non-zero word counts, `0` when `wordCount(input)` is `0`. Reuses `wordCount` from `@/lib/wordcount` rather than re-implementing word splitting.
- Added `__tests__/lib/truncate.test.ts` (5 cases) and `__tests__/lib/reading-time.test.ts` (7 cases including a single-word boundary case added during code-quality review).
- Spec delta in `openspec/changes/add-truncate-and-reading-time-helpers/specs/text-utilities/spec.md`: two `## ADDED Requirements` (truncate, readingTime) covering 11 spec scenarios total.
- No call sites are wired up. Helpers are additive; nothing existing is touched.
- No brainstorming spec was produced (no UI surface; scope was already pinned in conversation). Saved as a memory: skip brainstorming for simple non-UI `/opsx:propose` runs.

### 2. Add personal profile fields to Settings page (`add-profile-fields-to-settings`)

**Commit:** _pending_

**Feature:**

- Added a Profile section to `/settings`, placed between the page heading and the existing Email section, with three editable fields: `name`, `gender`, `birthday`. Single "Save profile" submit button updates all three atomically.
- Extended the better-auth `user` table with two nullable columns (`gender TEXT`, `birthday TEXT`) via the bootstrap in `lib/db.ts`. Schema additions are applied idempotently: fresh installs get them from the `CREATE TABLE IF NOT EXISTS` block; existing databases get them from a `PRAGMA table_info(user)` + `ALTER TABLE ... ADD COLUMN` block immediately after. Re-running boot is a no-op.
- Added `updateProfileSchema` and a `Gender` enum (`['male', 'female', 'non-binary', 'prefer-not-to-say']`) to `lib/validation.ts`. Rules: trimmed name 1–100 chars, zod enum for gender, regex + ISO round-trip + bounded-range refine for birthday (rejects future dates, dates before 1900-01-01, and calendar-invalid dates like `2026-02-30`).
- Added `updateProfile` server action to `app/settings/actions.ts`. Auth-gates via `auth.api.getSession`, parses with `updateProfileSchema`, sanitizes `name` via `DOMPurify.sanitize(..., { ALLOWED_TAGS: [] })`, runs a session-trusted parameterised UPDATE keyed by `session.user.id`, and `revalidatePath('/settings')`. `removeAccount` left untouched.
- Added `<ProfileForm>` (`'use client'`) at `app/settings/profile-form.tsx`. Split into `ProfileFormView` (presentational, prop-driven, exported for testability) and `ProfileForm` (wraps `useActionState(updateProfile, ...)`). Three labelled inputs with `htmlFor`/`id`, gender dropdown with placeholder "Select…" option, inline `<p role="alert">` for `state.fieldErrors[field]`, "Save profile" disabled while pending, transient "Saved" indicator on success.
- Wired the page: `app/settings/page.tsx` now does `db.query('SELECT name, gender, birthday FROM user WHERE id = ?').get(session.user.id)` after the auth check and passes the row into `<ProfileForm defaultValues={...} />`. Falls back to `session.user.name` for `name` if the profile row is missing.
- Brainstorming spec: `docs/superpowers/specs/2026-05-01-add-profile-fields-to-settings-design.md` (visual companion used for gender + birthday + layout questions).
- Spec delta: `openspec/changes/add-profile-fields-to-settings/specs/account-management/spec.md` adds 6 requirements covering Profile rendering, validation, sanitization, session-trust, auth gate, and idempotent schema bootstrap.

**Subagent dispatch behavior:**

- Group 1 (`lib/db.ts` schema vs `lib/validation.ts` schema) and group 2 + 3 (`app/settings/actions.ts` vs `app/settings/profile-form.tsx`) were both file-disjoint, so dispatched in parallel via `superpowers:subagent-driven-development` per the tasks.md `[parallel]` markers and the top-level dispatcher line. All four parallel subagents completed cleanly with no merge/write conflicts.
- Group 1 deviation: task 1.1 originally asked for a direct `__tests__/lib/db.test.ts` that imports `@/lib/db` and asserts via `PRAGMA table_info`. This is incompatible with this project's vitest infrastructure — vitest does not run under the Bun runtime, so `bun:sqlite` cannot be loaded. Existing tests like `__tests__/app/settings/actions.test.ts` mock `@/lib/db` for exactly this reason. The schema-explicit test was dropped; schema additions are verified indirectly through the action tests (group 2) which write to/read from `gender`/`birthday`. Documented in tasks.md.
